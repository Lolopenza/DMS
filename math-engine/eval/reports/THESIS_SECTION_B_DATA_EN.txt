1. SYSTEM CONTEXT (facts — do not invent)
================================================================================

Platform: MathLab (repo: DMS) — educational web platform for IT students.

Verification pipeline (math-engine, FastAPI, endpoint verify_answer):
  1) code-judge (LLM reviews code; code is NOT executed in sandbox)
  2) math-judge (LLM for Big-O / recurrence notation)
  3) symbolic (SymPy — deterministic, confidence 0.99 if correct, 0.35 if wrong)
  4) semantic (Gemini/Groq LLM judge — returns JSON: correct, confidence, feedback)
  5) semantic-fallback (when LLM fails or JSON unparseable — string/SymPy equivalence)

Each attempt stores: correct, confidence, verification_method, feedback in PostgreSQL
(table generated_problem_attempts). Confidence is NOT shown in the student UI in MVP;
no automated teacher review queue in MVP.

Benchmark tool: math-engine/eval/run_verification_benchmark.py
Benchmark cases: math-engine/eval/verification_benchmark.json (50 cases)
Ground truth: author-assigned teacher reference labels (groundTruthCorrect)

Run mode: --live (all 50 cases evaluated; 7 used real Gemini API, others deterministic
or reproducible LLM mocks as documented below)

9. LIMITATIONS (mandatory paragraph)
================================================================================

- N = 50 is a controlled benchmark, not a large-scale field study.
- 7 cases used live Gemini (non-deterministic); remaining LLM cases use fixed mocks
  for reproducibility — must be stated explicitly in thesis.
- Unit tests (pytest) validate pipeline logic, NOT Gemini accuracy — cite this
  benchmark instead.
- code-judge does not execute code — FP on logic bugs is an architectural limitation.
- factorial() expressions currently fail SymPy parsing in production — combinatorics
  templates may route to semantic path (acknowledged technical debt).
- Do NOT claim: Redis/RabbitMQ actively used, public nginx hosting, teacher review
  queue implemented, or pytest count equals LLM accuracy.

================================================================================
10. KEY CONCLUSIONS FOR THESIS
================================================================================

- SymPy symbolic path: 15/15 = 100% accuracy on parseable expressions (deterministic).
- Overall hybrid pipeline: 86% agreement with teacher ground truth (43/50).
- Main failure mode (live): Gemini empty feedback → JSON parse fail → semantic-fallback
  rejects valid prose answers (3 FN).
- Main failure mode (mock/code): LLM false positives on wrong code without sandbox (2 FP).
- Confidence score identifies low-trust cases but is not yet used for teacher workflow in MVP.
